# Dhatri — Architecture

Dhatri turns a photo of a prescription into a dose schedule, reminds the patient, alerts the caregiver live when a dose is missed, and runs a short Hindi voice check-in that flags symptoms that keep coming back.

This file is the technical source of truth. Scope, owners and dates are in `PLAN.md`.

---

## 1. Scope this architecture covers

| In | Out |
|---|---|
| Patient and caregiver roles | Doctor role (caregiver summary covers it) |
| Prescription photo ? AI draft ? human confirm | Handwriting accuracy guarantees |
| Dose reminders, missed-dose escalation | Push notifications (FCM) |
| Live caregiver alerts over a stream | Real phone calls (Exotel) |
| In-app Hindi check-in (speech in, speech out) | Piper / IndicF5 / voice-engine abstraction |
| Repeated-symptom detection with SQL | pgvector / embeddings |
| Weekly caregiver summary | Offline sync |

```text
 Patient phone (Flutter)            Caregiver phone (Flutter)
          \                                  /
           \---- Serverpod client + shared WebSocket ----/
                              |
                         SERVERPOD 4
   ?????????????????????????????????????????????????????????
   ? Auth: serverpod_auth_idp, email provider, JWT         ?
   ? Postgres models: Profile, Prescription, Medication,   ?
   ?   DoseEvent, WellnessCheck, SymptomReport, Alert      ?
   ? File storage: 'private' (prescription photos)         ?
   ? Future calls: extract, remind, escalate, check-in     ?
   ? Recurring task: daily check-in per patient (cron)     ?
   ? Streams: channel "patient_{id}" carries CareUpdate    ?
   ?????????????????????????????????????????????????????????
                 |                          |
        Gemini (gemini-3.8-flash)     Sarvam AI
        image ? JSON schedule         saaras:v4  speech ? text (hi-IN)
        transcript ? JSON + reply     bulbul:v3  text ? speech (hi-IN)
```

**The one rule every feature follows:** change the row in Postgres, then post a `CareUpdate` to `patient_{id}`. Both phones listen to that channel. This is what makes the missed-dose alert appear live on the caregiver's phone.

## 5. Endpoints

Every endpoint overrides `requireLogin => true` and calls `requireAccess(session, patientId)` from `services/access.dart` before touching data.

`requireAccess` passes only if the caller's `Profile` is that patient, or is the caregiver linked to that patient. Roles live on `Profile` instead of Serverpod scopes, because changing a scope does not apply until the user signs in again.

| Endpoint | Method | Caller | Does |
|---|---|---|---|
| `ProfileEndpoint` | `me()` ? `Profile?` | both | Current profile, null before onboarding |
| | `register(String name, Role role)` ? `Profile` | both | Creates profile; patients get a 6-digit `linkCode` |
| | `linkPatient(String code)` ? `Profile` | caregiver | Sets `caregiverId` on the patient with that code |
| | `myPatient()` ? `Profile?` | caregiver | The linked patient |
| `PrescriptionEndpoint` | `uploadTicket(int patientId)` ? `UploadTicket` | caregiver | `createUploadDescription(storageId: 'private', path: 'prescriptions/{patientId}/{uuid}.jpg')` |
| | `submit(int patientId, String path)` ? `Prescription` | caregiver | `verifyUpload`, insert row, schedule `extract` with zero delay |
| | `drafts(int prescriptionId)` ? `List<MedicationDraft>` | caregiver | Parsed from `extractedJson` |
| | `confirm(int prescriptionId, List<MedicationDraft> meds)` ? `List<Medication>` | caregiver | Inserts medications, creates dose events, schedules `remind` for each |
| `DoseEndpoint` | `today(int patientId)` ? `List<DoseEvent>` | both | Today in IST |
| | `markTaken(int doseEventId)` ? `DoseEvent` | patient | `transition(reminded or scheduled ? taken)`, post update |
| `CheckInEndpoint` | `startNow(int patientId)` ? `void` | caregiver | Schedules `CheckInFutureCall.open` with zero delay |
| | `question(int checkId)` ? `CheckInTurn` | patient | Hindi greeting text + TTS audio |
| | `answer(int checkId, ByteData audio)` ? `CheckInTurn` | patient | STT ? Gemini ? store ? repeat rule ? reply text + audio |
| `AlertEndpoint` | `acknowledge(int alertId)` ? `Alert` | caregiver | Sets `acknowledgedAt`, post update |
| `SummaryEndpoint` | `week(int patientId)` ? `WeekSummary` | caregiver | Counts over the last 7 days |
| `CareStreamEndpoint` | `watch(int patientId)` ? `Stream<CareUpdate>` | both | Subscribes to `patient_{id}` |

```dart
class CareStreamEndpoint extends Endpoint {
  @override
  bool get requireLogin => true;

  Stream<CareUpdate> watch(Session session, int patientId) async* {
    await requireAccess(session, patientId);
    yield* session.messages.createStream<CareUpdate>('patient_$patientId');
  }
}
```

Posting from anywhere on the server:

```dart
await session.messages.postMessage(
  'patient_${event.patientId}',
  CareUpdate(doseEvent: event),
);
```

## 6. Scheduled work (future calls)

Future calls are stored in Postgres and survive restarts. Accessor names drop the `FutureCall` suffix: `DoseFutureCall` is `futureCalls...dose`.

| Call | Scheduled by | Behaviour |
|---|---|---|
| `PrescriptionFutureCall.extract(int prescriptionId)` | `submit()`, `callWithDelay(Duration.zero)` | `uploaded ? extracting`, read image from storage, Gemini extraction, store JSON, `? extracted` (or `failed` with `error`), post update |
| `DoseFutureCall.remind(int doseEventId)` | `confirm()`, `callAtTime(scheduledAt)` | `scheduled ? reminded`, post update, schedule `escalate` after the grace period |
| `DoseFutureCall.escalate(int doseEventId)` | `remind()`, `callWithDelay(grace)` | If still `reminded`: `? missed`, insert `Alert(missedDose)`, post update |
| `CheckInFutureCall.open(int patientId)` | `callRecurring(identifier: 'checkin-{patientId}').cron('30 13 * * *')` (19:00 IST) on link, and `startNow()` | Insert `WellnessCheck(pending)`, post update; the patient's phone opens the check-in screen |

```dart
await session.serverpod.futureCalls
    .callAtTime(event.scheduledAt)
    .dose
    .remind(event.id!);
```

### Rule 1: every job must be safe to run twice

Serverpod 4 runs future calls at least once, so a crash can repeat a call. Every status change is "move from X to Y, or do nothing". A repeated `escalate` finds `missed`, not `reminded`, and creates no second alert.

### Rule 2: Taken and escalate can race

A patient can tap Taken in the same instant `escalate` fires. `services/dose_rules.dart` runs every status change in a serializable transaction. When Postgres reports a serialization failure, the other side won, and this side returns `false`.

```dart
Future<bool> transition(
  Session session,
  int id, {
  required Set<DoseStatus> from,
  required DoseStatus to,
}) async {
  try {
    return await session.db.transaction(
      (tx) async {
        final event = await DoseEvent.db.findById(session, id, transaction: tx);
        if (event == null || !from.contains(event.status)) return false;
        await DoseEvent.db.updateRow(
          session,
          event.copyWith(
            status: to,
            takenAt: to == DoseStatus.taken ? DateTime.now().toUtc() : event.takenAt,
          ),
          transaction: tx,
        );
        return true;
      },
      settings: TransactionSettings(isolationLevel: IsolationLevel.serializable),
    );
  } on DatabaseQueryException catch (e) {
    if (e.code == PgErrorCode.serializationFailure) return false;
    rethrow;
  }
}
```

### Grace period

Read from the environment variable `DHATRI_GRACE_MINUTES`, default `20`. Set it to `1` while filming so the alert fires on camera without editing.

### Creating dose events

`confirm()` creates every dose event from `startDate` to `startDate + durationDays`, capped at 30 days, for each time in `times`. Times are IST (UTC+5:30, no daylight saving) and converted to UTC before insert. The unique index on `(medicationId, scheduledAt)` stops duplicates if `confirm()` is retried.

## 7. AI and voice services

All external calls are made from the server. API keys never reach the phone. Both services use `package:http`.

### Secrets

`dhatri_server/config/passwords.yaml` (gitignored):

```yaml
shared:
  geminiApiKey: '...'
  sarvamApiKey: '...'
```

Read with `session.serverpod.getPassword('geminiApiKey')`. In production, use `SERVERPOD_PASSWORD_geminiApiKey`.

### Gemini — `services/gemini.dart`

`POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, header `x-goog-api-key`.

Model id comes from config, default `gemini-3.8-flash`, because model names change.

Structured output: `generationConfig.responseFormat.text = { mimeType: 'application/json', schema: {...} }`.

**`extractPrescription(Uint8List image, String mimeType)`** sends the image as `inline_data` with this schema:

```json
{
  "type": "object",
  "properties": {
    "unreadable": { "type": "boolean" },
    "medications": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "name": { "type": "string" },
          "strength": { "type": ["string", "null"] },
          "doseText": { "type": "string" },
          "instructions": { "type": ["string", "null"] },
          "times": { "type": "array", "items": { "type": "string", "description": "HH:mm, 24h" } },
          "durationDays": { "type": "integer" }
        },
        "required": ["name", "doseText", "times", "durationDays"]
      }
    }
  },
  "required": ["unreadable", "medications"]
}
```

The prompt maps common abbreviations to times: OD ? 08:00, BD ? 08:00 and 20:00, TDS ? 08:00, 14:00 and 20:00, HS ? 22:00. The caregiver always reviews the result before anything is scheduled.

**`interpretCheckIn(String transcript, List<SymptomReport> lastWeek)`** returns:

```json
{
  "mood": "good | okay | low",
  "symptoms": [{ "symptom": "weakness", "severity": 3 }],
  "replyHi": "short Hindi reply, at most two sentences, no medical advice"
}
```

`symptom` is constrained to the fixed list with a schema `enum`. The prompt includes last week's reports so the reply can refer to them, for example "???? ???? ?? ?????? ???? ??". This is the patient memory: SQL rows in the prompt, no embeddings.

System prompt rules: never diagnose, never change a dose, suggest contacting the caregiver or doctor when severity is 4 or more.

### Sarvam — `services/sarvam.dart`

Header `api-subscription-key`.

**`transcribe(Uint8List audio)`**: `POST https://api.sarvam.ai/speech-to-text`, multipart, `file`, `model=saaras:v4`, `language_code=hi-IN`. Returns `transcript`. Audio must be under 30 seconds.

**`speak(String text)`**: `POST https://api.sarvam.ai/text-to-speech`, JSON:

```json
{ "text": "...", "language_code": "hi-IN", "model": "bulbul:v3", "speaker": "ritu", "pace": 0.9 }
```

Returns `audios[0]`, base64 WAV, decoded into `ByteData` for `CheckInTurn.audio`.

### Check-in pipeline (`CheckInEndpoint.answer`)

```text
audio (AAC from phone)
  ? Sarvam transcribe (hi-IN)
  ? load last 7 days of SymptomReport (SQL)
  ? Gemini interpretCheckIn
  ? update WellnessCheck (completed, transcript, mood, replyText)
  ? insert SymptomReport rows
  ? repeat rule
  ? Sarvam speak(replyHi)
  ? return CheckInTurn, post CareUpdate(check)
```

### Repeat rule — `services/symptom_rules.dart`

For each symptom in the new check-in:

```dart
final count = await SymptomReport.db.count(
  session,
  where: (t) =>
      t.patientId.equals(patientId) &
      t.symptom.equals(symptom) &
      (t.reportedAt > DateTime.now().toUtc().subtract(const Duration(days: 7))),
);
```

If `count >= 3` and there is no unacknowledged `repeatedSymptom` alert for that symptom, insert `Alert(kind: repeatedSymptom, symptom: ..., message: 'Weakness reported 3 times in 7 days')` and post it.

### `care_stream.dart`

One subscription to `client.careStream.watch(patientId)` for the whole app, exposed as a `Stream<CareUpdate>` to screens.

Streams close when the WebSocket drops. On error or done: wait 2 seconds, resubscribe, then call `today()` again so an update missed during the gap still shows.

### Uploads

```dart
final ticket = await client.prescription.uploadTicket(patientId);
final ok = await FileUploader(ticket.description).upload(stream, length);
if (ok) await client.prescription.submit(patientId, ticket.path);
```

`FileUploader.upload` returns `false` without a reason on failure. Show a retry button.

## 9. Configuration and known limits

| Issue | Fix |
|---|---|
| Default `maxRequestSize` is 512 KiB; photos and audio exceed it | Set `maxRequestSize: 5242880` in `development.yaml` and `production.yaml`. Pick photos with `maxWidth: 1600, imageQuality: 80`. Record AAC, 16 kHz, mono |
| Sarvam REST speech-to-text accepts under 30 seconds | Stop recording at 25 seconds |
| Handwritten prescriptions misread | Use a printed prescription in the video. The review screen is the safety net |
| Time zones | Store UTC. Medication times are IST. Convert at the edge |
| Future calls repeat | Guarded status transitions (section 6) |
| Email sign-up needs verification codes | In development, log the code on the server. Seed demo accounts before filming |
| Secrets | `passwords.yaml` is gitignored. Share keys privately, never in chat logs or the repo |

## 10. Tests

One integration test file, `test/integration/dose_escalation_test.dart`, using Serverpod's test tools:

1. A dose never marked taken becomes `missed` after `escalate`, with exactly one alert, even when `escalate` runs twice.
2. A dose marked taken before `escalate` stays `taken`, with no alert.
3. Three weakness reports in 7 days create one `repeatedSymptom` alert. A fourth does not create a second one.
